# План за продуктов импорт и синхронизация с Microinvest

Този документ описва договореното разделение между:

- първоначален импорт от WordPress базата
- първоначално синхронизиране с Microinvest
- регулярна комуникация с Microinvest след пускането

## Първоначален импорт от WP-базата

- Име
- Описание
- Съвместим с марки
- Категории
- SKU
- Оригинален код
- Производител
- `slug`
- Снимки: `legacyUrl`
- Снимки: `storageKey`, ако вече съществува
- Останалите legacy данни по продукта
- Ако продуктът вече съществува: `update`
- Ако продуктът не съществува: `create`

## Първоначално синхронизиране с МИ

- Връзване по `SKU`
- `miProductId`
- Цена на дребно
- Цена на едро
- Цена за ценова група 1
- Наличност (бр.)
- Статус наличност
- Публикуван
- Не пипаме: Оригинален код
- Не пипаме: Производител
- Не пипаме: Описание, категории, марки и снимки

## Регулярна комуникация с МИ

- За нови продукти: създаване на нов запис
- За съществуващи продукти: обновяване на оперативните данни
- Цени
- Наличност
- Публикуван
- За новодобавените продукти занапред: Име
- За новодобавените продукти занапред: Оригинален код
- За новодобавените продукти занапред: Производител

## Допълнителни уточнения

- При първоначалното синхронизиране с МИ не трябва да презаписваме `Оригинален код` и `Производител` за старите продукти, защото тези данни в момента са по-надеждни в стария сайт.
- След пускането МИ става оперативен източник за новите продукти и за регулярните промени по цени, наличности и публикуване.
- Снимките не трябва да се губят при нов импорт. Ако продуктът вече съществува, записът трябва да се обновява, без да се занулява полето `images`.
- За снимките предпочитаният източник в сайта е:
  1. `storageKey`
  2. `media.url`
  3. `legacyUrl`
