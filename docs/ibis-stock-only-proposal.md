# Предложение за stock-only договор NIK → Ibis BG

**Само за съгласуване. Няма имплементиран или активиран нов изпращащ път.**
BG repository-то не се променя в този PR. Положителната `priceGroup1` е единствената
цена за приемане на Ibis поръчки; retail цената не участва в приемането.

## Заявка

Предлагаме нов event на съществуващия BG webhook endpoint, конфигуриран чрез
`IBIS_SYNC_WEBHOOK_URL`. Методът е `POST`, `Content-Type: application/json`,
автентикацията е съществуващият `x-webhook-secret`. Няма нов URL или нов ключ.

```json
{
  "event": "product.stock_updated",
  "items": [
    { "sku": "167MI07", "stockQty": 0 }
  ]
}
```

Всеки ред има точно две полета. `sku` е точният, чувствителен към регистъра SKU
(1–128 символа, без външни интервали и контролни символи). `stockQty` е крайно
неотрицателно JSON число, включително `0`; то заменя абсолютно наличността,
не се прибавя или изважда. Допускат се дробни количества, съвместими с наличния
каталог. `items` съдържа 1–500 реда с уникални SKU. Липсващо количество не означава 0.
Няма цена, заглавие, изображения, публикуваност или друго съдържание.

BG намира точно един съществуващ продукт по SKU. Не създава продукт и не променя
цени, съдържание или ръчно зададен статус. Нееднозначният SKU е `invalid`.
При невалиден ред останалите валидни редове се обработват.

## Очакван отговор

```json
{
  "event": "product.stock_updated",
  "items": [
    { "sku": "167MI07", "status": "updated", "stockQty": 0 },
    { "sku": "MISSING", "status": "not_found" },
    { "sku": "BAD", "status": "invalid" }
  ]
}
```

Това е пример за три подадени SKU. HTTP `200` изисква точно един резултат за всеки
подаден SKU. `updated` се връща само след успешно записване и включва записаното
количество, равно на заявеното. `not_found` и `invalid` са неуспех за съответния ред.
Невалидна обща структура връща `400`; невалидна автентикация — `401` или `403`.
HTTP грешка, невалидно тяло, непознат/дублиран/липсващ резултат или несъвпадащо
количество не доказват успешна синхронизация. Не са нужни общи броячи за успех.

При повторение NIK прочита текущите абсолютни количества от базата. BG трябва
да приеме повторно същото количество без допълнително намаляване. Абсолютните
стойности сами по себе си не решават доставяне извън ред между различни заявки;
този минимален договор не обещава версия или глобална последователност.

Активиране се допуска едва след съгласуване, поддръжка от BG и отделна проверена
промяна в NIK. Дотогава действа `product.price_stock_updated`: артикули без валидна
retail цена се записват като неуспешни, а останалите продължават независимо.
